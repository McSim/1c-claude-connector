# 1С-коннектор для Claude

Расширение для Claude Desktop, которое подключает Claude к вашей 1С через стандартный интерфейс OData. Вы задаёте вопрос обычными словами («5 последних реализаций», «остатки по складам», «сколько номенклатуры»), Claude сам строит запросы и показывает данные.

**Только чтение.** Коннектор выполняет исключительно GET-запросы. Записи в 1С нет даже как опции.

## Возможности

- Прямое подключение с вашего компьютера или через сервер-посредник по SSH (для 1С, которая пускает только IP из белого списка). На сервер ничего устанавливать не нужно.
- Пять инструментов: `check_connection`, `list_objects`, `describe_object`, `query`, `count`.
- Остатки и обороты регистров (`Balance()`, `Turnovers()`), последние значения регистров сведений (`SliceLast()`).
- Названия вместо GUID в одном запросе: `select=Number,Контрагент/Description`.
- Пошаговая проверка связи с понятными причинами ошибок, включая разрешённые сервером методы входа по SSH.
- Логин и пароли вводятся в форме Claude Desktop и хранятся в Credential Manager (Windows) или Keychain (macOS). В чат они не попадают.

## Установка

1. Скачайте файл `1c-connector.mcpb` из раздела Releases.
2. Откройте его двойным кликом и выберите Claude (или перетащите в окно Claude Desktop, раздел «Расширения»).
3. Заполните форму:
   - **Адрес OData**: адрес от технического специалиста, например `http://server/base/odata/standard.odata/` (окончание можно не писать).
   - **Логин и пароль 1С**: пользователь с правами только на чтение.
   - **Описание базы** (необязательно): подсказка для Claude, например «УТ 11, оптовая торговля».
4. Включите расширение, откройте новый чат и напишите: «проверь связь с 1С».

После изменения настроек выключите и снова включите расширение: настройки читаются при запуске.

## Что нужно подготовить в 1С

Попросите технического специалиста:

> Опубликуйте базу через OData, настройте состав: номенклатура, контрагенты, цены, остатки, продажи. Создайте пользователя только на чтение и пришлите адрес, логин и пароль.

Подробности публикации: [настройка OData](https://github.com/evilbruce666/1c-odata-mcp/blob/main/docs/ODATA-SETUP.md).

## Если 1С закрыта белым списком IP

Нужен сервер в интернете, IP которого добавлен в белый список 1С. Коннектор откроет SSH-туннель к этому серверу и пойдёт в 1С с его адреса. В форме заполните:

- **Сервер-посредник**: IP сервера (порт SSH, если не 22: `203.0.113.10:2222`).
- **Логин сервера (SSH)** и **пароль сервера (SSH)**, либо **SSH-ключ** (файл приватного ключа), если сервер пускает только по ключу.

На сервере должна быть разрешена пересылка соединений (`AllowTcpForwarding yes`, включена по умолчанию).

### Рекомендуемая настройка сервера

Не используйте root. Заведите отдельного пользователя только для туннеля, без shell и с пересылкой на один адрес (замените адрес 1С на свой):

```bash
adduser --shell /usr/sbin/nologin --gecos "" --disabled-password tunnel1c
passwd tunnel1c
```

```bash
cat > /etc/ssh/sshd_config.d/99-1c-tunnel.conf <<'EOF'
Match User tunnel1c
    PasswordAuthentication yes
    AllowTcpForwarding yes
    PermitOpen 203.0.113.50:80
    PermitTTY no
    X11Forwarding no
    ForceCommand /usr/sbin/nologin
EOF
sshd -t && systemctl reload ssh
```

Отпечаток ключа сервера запоминается при первом подключении (`~/.1c-connector/known_hosts.json`). Если он изменится, коннектор откажется подключаться и сообщит об этом.

## Безопасность и ограничения

- Только чтение: любые методы кроме GET не используются. Дополнительно ограничьте права пользователя в самой 1С.
- Если OData опубликован по `http://`, логин и пароль 1С идут по сети открыто. Для постоянной работы настройте https.
- Данные, которые коннектор достаёт из 1С, попадают в диалог с Claude и обрабатываются сервисом Anthropic. Если в базе есть персональные данные, оцените это с точки зрения 152-ФЗ: начинайте с агрегатов и справочников без персональных данных.
- Ответ обрезается на 150 КБ, строк в одном запросе не больше 500. Большие выборки читаются порциями.
- Работает с Claude Desktop (Windows и macOS). Для ChatGPT нужен удалённый MCP-сервер по https, это отдельная задача.

## Частые проблемы

| Симптом | Что делать |
| --- | --- |
| Windows спрашивает, чем открыть `.mcpb` | Выберите Claude |
| Изменили настройки, ничего не поменялось | Выключите и включите расширение |
| Таймаут или 502 | IP не в белом списке 1С: нужен сервер-посредник из белого списка |
| Сервер не принял логин или пароль SSH | `check_connection` покажет, какие методы входа разрешены: пароль, ключ или оба |
| Сервер пускает только по ключу | Выберите файл приватного ключа в поле «SSH-ключ» |
| Сертификат https самоподписанный | Включите «Разрешить самоподписанный сертификат» |

## Разработка

```bash
npm install
npm test        # сценарии на имитации 1С и SSH-сервера
npm run pack    # чистит нативные модули, валидирует, собирает dist/1c-connector.mcpb
```

Собирать пакет нужно только через `npm run pack`: он удаляет собранные под одну ОС нативные модули ssh2, чтобы расширение работало и на Windows, и на macOS. В `.mcpbignore` шаблоны указываются от корня (`/dist/`, `/tests/`), иначе из пакета выпадают одноимённые папки внутри `node_modules`.

Перед новой версией: поднимите `VERSION` в `server/index.js` и `version` в `manifest.json`, `package.json`, `package-lock.json`, прогоните тесты, соберите и распакуйте `.mcpb` (`npx @anthropic-ai/mcpb unpack`), проверив, что внутри есть `node_modules/@modelcontextprotocol/sdk/dist/esm/server/mcp.js`.
