# План пилота и адаптации OData-коннектора для Data Service

Дата проверки 13 октября 2026. Базовая версия `bba54ccf645624fcc383b652f0d7e9ba0b1bac49`, приложение 1.3.2.

## Решение

Использовать как компактную основу собственного помощника для чтения данных 1С. Сначала подтвердить OData и точность результатов на одной изолированной тестовой базе. Затем добавить предметные инструменты Data Service, не расширяя доступ до выполнения BSL.

Никакой реальной базы здесь не подключали. В этой ветке сохраняется план, исходники пока не меняются.

## Техническая возможность самостоятельной доработки

Основная логика находится в server/index.js, около 550 строк. Есть manifest.json, package-lock.json, сборка MCPB и тесты с имитацией OData и SSH. Закрытого сервиса автора в проверенном маршруте нет.

Сервер реализует MCP через stdio и не вызывает модель. Claude Desktop нужен для готовой упаковки MCPB и формы настроек, но сам Node.js-процесс можно подключать к другому локальному клиенту, поддерживающему запуск stdio-сервера. Конкретную совместимость проверить отдельно.

Для облачного ChatGPT потребуется самостоятельная реализация удалённого HTTP-транспорта и аутентификации. Это отдельная работа, не необходимая для начального пилота.

| Изменение | Где выполняется | Сложность |
|---|---|---|
| Инструкции и описание EE/UT Baltics | Инструкции MCP и DB_DESCRIPTION | Небольшая |
| Готовые запросы и проверки | Новые инструменты в server/index.js | Умеренная |
| Перечень разрешённых объектов и полей | Проверка до HTTP-запроса | Небольшая или умеренная |
| Проверка и маскировка чувствительных значений | Слой подготовки результатов и ошибок | Умеренная |
| Несколько баз | Сначала отдельный процесс на базу | Небольшая для пилота |
| Общий сервис с несколькими клиентами | Новый транспорт, учётные записи и изоляция | Существенная |
| Произвольные BSL-запросы, журналы и запись | Дополнительный механизм внутри 1С | За пределами исходной архитектуры |

В LICENSE и manifest.json указана MIT, в package.json ISC. Перед распространением собственной сборки уточнить несогласованность и сохранить уведомления лицензии и авторства.

## Что уже реализовано

Пять MCP-инструментов:

- check_connection, пошаговая проверка подключения.
- list_objects, обнаружение опубликованных объектов.
- describe_object, поля из OData metadata.
- query, GET-выборки с select/filter/expand/top/skip.
- count, количество записей.

HTTP-запросы формируются с методом GET. Код поддерживает Balance(), Turnovers() и SliceLast() в пути, но доступность и правильность этих функций для наших конфигураций требуется подтвердить.

Нет выполнения произвольного BSL, записи документов, журнала регистрации и технологического журнала. Расширение функциональности ограничено тем, что отдаёт стандартный OData.

## Минимальный стенд

1. Одна изолированная демонстрационная база либо копия EE/UT Baltics с отключёнными обменами, фоновыми заданиями и внешними подключениями. Первый запуск лучше на синтетических данных.
2. Опубликованный стандартный OData. Состав публикации ограничен объектами для трёх проверочных задач.
3. Отдельная учётная запись 1С только с нужными правами чтения, без административных прав. Проверить реальные запреты на чтение лишних объектов и операции записи.
4. Windows с Claude Desktop для проверки существующей готовой упаковки. Если выбирается другой клиент, настроить Node.js >=18 и stdio.
5. Для каждого подключения отдельный процесс, адрес базы и учётная запись. Не переносить секреты между клиентскими базами.

Доступ к компьютеру клиента, версии платформы, состав OData и MCP-клиент в этой сессии не определены.

## Настройка без правок исходников

- Установить готовый MCPB либо запустить node server/index.js через MCP-клиент.
- Задать ODATA_URL, ODATA_USERNAME, ODATA_PASSWORD и краткое DB_DESCRIPTION.
- Предпочесть HTTPS с проверкой сертификата. ALLOW_SELF_SIGNED оставить выключенным; постоянную работу организовать с доверенным сертификатом.
- SSH-посредник добавлять только при необходимости. Для первого подключения сверить отпечаток сервера независимо, так как код применяет доверие при первом подключении.
- Пароли в готовом MCPB отмечены sensitive, их хранение организует приложение-хост. Сам сервер получает их через переменные окружения. При другом клиенте нельзя автоматически обещать защищённое хранилище.
- Не включать автозапуск на всех клиентских базах до проверки результатов.

## Что доработать под себя

### Первый предметный слой

После проверки generic query добавить один выбранный инструмент с заданным смыслом показателя, например остатки по товару и складу на дату.

Контракт должен явно определять дату и момент среза, единицы, склад, включение резервов и прочие отборы. ИИ выбирает параметры и объясняет ответ; технический расчёт задаётся проверенным кодом.

В инструкции зафиксировать источники показателей EE/UT Baltics, ограничения и примеры. Название инструмента не должно обещать свободный остаток, если он возвращает физический.

### Ограничение данных

В текущем коде нет общего списка разрешённых объектов и полей и нет слоя анонимизации. Ограничения публикации OData и прав 1С являются первичными.

При создании ограниченного помощника добавить проверку разрешённых объектов, полей и переходов expand ДО запроса. Применить её к query, count и describe_object, согласовать список, возвращаемый list_objects. Проверить полный путь, виртуальные таблицы и вложенные переходы. Простая проверка префикса строки недостаточна.

До передачи чувствительных данных модели настроить состав и правила выдачи либо подготовить обезличенную тестовую базу. Исходный коннектор не гарантирует, что ФИО, контакты или банковские данные останутся локально. Данные, возвращённые в чат, обрабатываются выбранным ИИ-сервисом.

### Устойчивость

Лимит query составляет 500 строк, ответ обрезается до 150000 символов. Это не предел HTTP-загрузки, код сначала собирает ответ в памяти. Для большого объёма добавить лимит байтов при чтении и проверяемую постраничную обработку.

Обрезание JSON как текста может дать неполную структуру. Для специальных инструментов лучше возвращать ограниченный валидный результат с явными признаками неполноты.

Разбор XML metadata выполняется регулярными выражениями. При проблемах на наших публикациях перейти к XML-парсеру и добавить регрессионные примеры.

Запретить перенаправление HTTPS на HTTP, даже если сервер тот же, для постоянной установки. В текущем коде проверяется изменение host, но отдельный запрет понижения схемы не обнаружен.

Эти изменения являются планом, в этой ветке не реализованы.

## Три проверки на реальной тестовой базе

| Проверка | Эталон |
|---|---|
| Документ с контрагентом и строками | Совпадают ссылка, реквизиты, суммы и количества |
| Остаток товара по складу и дате | Совпадает с отчётом при тех же параметрах |
| Последнее значение цены на заданную дату | Совпадают вид цены, валюта, единица и дата |

Сначала получить эталон средствами 1С. ИИ должен объяснить источник и ограничения. Отдельно проверить, что неполную выборку он не выдаёт за итог по всей базе.

## Уже проведённая проверка

На этой версии установлены зависимости через npm ci --ignore-scripts и запущен npm test. На имитациях 1С и SSH прошли 57 сценариев, один не прошёл. Проверка несуществующего домена ожидала ошибку DNS, но среда вернула HTTP 502. Это результат тестов в данной среде, а не подтверждение корректности с реальной 1С.

Тестовый набор вывел итог 57/1, но завершился кодом 0. Перед использованием npm test в CI исправить suite.mjs так, чтобы ненулевое число ошибок возвращало ненулевой код завершения. Это небольшая необходимая правка процесса разработки.

Готовый пакет pack ещё не собирали и не устанавливали в Claude Desktop. EE и UT Baltics не тестировались.

## Критерий решения после пилота

Продолжать, если три эталона совпали, доступ действительно ограничен, неполные ответы явно обозначены и специальный инструмент помогает сотруднику работать быстрее или точнее.

Первую собственную сборку сопровождать версиями, тестами и перечнем изменений в отдельной ветке. main оставить для обновлений upstream.

## Следующее действие

Выбрать тестовую базу и клиента, подтвердить OData. Запустить неизменённый коннектор на синтетических данных. После этого исправить код завершения тестов и реализовать один предметный инструмент с ограничением данных в отдельной ветке.
